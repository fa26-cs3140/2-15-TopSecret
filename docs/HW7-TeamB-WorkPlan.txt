HW7 Team Member B (Control) - Work Plan
=======================================

Role: the editing workflow. Administrators can create and edit records in the web view.
A new record starts from an empty form with fields for its type; editing starts from a
form filled with the record's current values. Styling comes from Team A's CSS. Users and
account details are still managed only in the terminal.

Branch: work happens on short branches cut from NewDatabaseManagerRefactor and merged back
through pull requests into NewDatabaseManagerRefactor (never straight into main).


1. Design
---------

URLs (all require a valid session; all editing requires admin):

  GET  /<type>/new         empty form for a new record
  POST /<type>/new         create the record, then 303 redirect to /<type>/<id>
  GET  /<type>/<id>/edit   form filled with the record's current values
  POST /<type>/<id>/edit   update the record, then 303 redirect to /<type>/<id>

  <type> is briefs, agents, facilities, missions or countries.
  Non-admins get 403 "Access denied". An unknown type or ID gets 404.
  Invalid input re-shows the same form with an error message and the values the user
  typed, so nothing is lost (status 200, no redirect).

Classes:

  org.controller.EditHandler   (new) parses edit URLs and runs the GET/POST workflow.
                               PageHandler hands it any /new or /<id>/edit request after
                               the session check, so login handling stays in one place.
  org.controller.RecordForms   (new) lists the form fields for each record type.
  org.controller.AppController (extended) shared control logic for the web and terminal:
                                 canEdit(user)
                                 formValues(type, id)          current values for the edit form
                                 createRecord(type, values, user)  validates, saves, logs CREATE
                                 updateRecord(type, id, values, user)  validates, saves, logs UPDATE
  org.view.FormField           (new) one form input: name, label, kind, required.
  org.view.FormView            (new) renders a form as plain HTML. Team A's CSS styles it;
                               no inline styles and no JavaScript.

Edit and create links: list pages get a "New <type>" link and detail pages get an "Edit"
link, shown only to admins.

6. Refactoring (B's code), in priority order
--------------------------------------------

  1. PageHandler.handle is one long method. Split it into small route methods (menu, audit,
     list, detail) so edit routes can be added cleanly and each route is testable.
  2. AppController repeats getRecords("id", "%").stream().filter(id) for every type. Use
     one lookup helper (or a getRecord(id) from the managers if Team D adds one).
  3. LoginHandler.parseForm is used by login and will be used by EditHandler. Move it to
     WebServer next to send() and redirect().
  4. ProgramControl.run is long and mostly untested (50% line coverage). Split account
     creation and login into their own methods and test them.
  5. Null checks: AppController and ProgramControl constructors accept a null
     MissionManager. Reject it like the other managers.
  6. ProgramControl still has a "TODO: Figure out how cipher works" comment and HW4-era
     getFileContents methods; remove what is no longer used.
