Homework 6 - Team Member B (Controller)
Work Plan

Branch: member-b-web (merged into main through a pull request at the end of each week)


Goal

Add a web view to Top Secret while keeping the terminal as the default interface.
Terminal and web navigation share one controller so the control logic is written once.


Requirements (Team Member B)

1. Running with no arguments starts the terminal interface, as it does now.
2. Running with -web starts an HTTP server on port 3002 instead.
3. http://localhost:3002/ shows a login form (username and password).
4. Valid credentials: the server sends a session cookie and shows the main menu page.
   The cookie has no Expires or Max-Age, so it is deleted when the browser closes.
5. Invalid credentials: the login form is shown again with an error message.
6. Every page except the login page requires a valid session cookie.
   Requests without one are redirected to the login page.
7. The web server does not start if no user accounts exist. The program prints a message
   telling the user to create the first account in the terminal.
8. Terminal and web navigation work the same way and share control logic.


Design

Package: org.controller (the team's model/view/controller layout: org.model, org.managers,
org.view, org.controller, org.runtime).

LaunchOptions
- isWebMode(args): true when the arguments contain -web.

AppController (shared by terminal and web)
- listRecords(type): text listing of briefs, agents, or facilities.
- readRecord(type, id, user): text details of one record; records a READ audit entry.
- auditLog(user): text audit log for admins; an access-denied message otherwise.
- Returns plain text. The terminal prints it; the web view (Team C) wraps it in HTML.

SessionManager
- createSession(user): creates a random token (SecureRandom) and remembers its user.
- getUser(token): user for a token, or null.
- endSession(token): forgets a token (logout).
- Sessions are kept in memory only. Restarting the server logs everyone out.
- No database table is added, so the ERD is unchanged by Team Member B.

WebServer
- Uses the JDK's built-in com.sun.net.httpserver.HttpServer (no web frameworks).
- start(): refuses to start (IllegalStateException) when no user accounts exist.
- stop(), getPort(). The port is a constructor argument so tests can use another port.

LoginHandler
- GET /        login form (or a redirect to /menu when the session is valid)
- POST /login  checks credentials with UserAccountManager.verifyLogin()
               valid: Set-Cookie: session=<token>; HttpOnly; Path=/   then redirect to /menu
               invalid: login form with an error message, no cookie
- The password is sent in the POST body, never in the URL.
- Users that exist but have no password yet are told to set it in the terminal first.

PageHandler
- Checks the session cookie, then maps the URL to an AppController call.


Navigation (terminal menu -> web URL)

Main menu                     /menu
1 Briefs -> 1 List            /briefs
1 Briefs -> 2 Read -> id      /briefs/{id}
2 Agents                      /agents, /agents/{id}
3 Facilities                  /facilities, /facilities/{id}
4 Review audit log (admin)    /audit
Missions (Team A, new)        /missions, /missions/{id}
Logout                        /logout

Creating, editing, password changes, and messages stay terminal-only for this release.
