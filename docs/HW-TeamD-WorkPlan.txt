Homework 5 - Team Member D Work Plan
User Accounts and Audit Log

Scope

Team Member D owns multiple user accounts and the audit log.
Password data remains outside SQLite in ciphered files.
Account metadata and audit records are stored in SQLite.

Implemented Account Design

UserAccount
- username
- admin flag
- no password field

UserAccountManager
- validates Homework 5 usernames
- validates Homework 5 password rules
- reports whether any users exist
- creates ordinary users without setting their password
- creates the first user as an admin
- supports first-time password setup by the associated user
- verifies login
- changes a user's password
- reads user-account metadata

UserAccountStore / SqliteUserAccountStore
- separates account business logic from SQLite persistence
- creates the users table when necessary
- stores username and is_admin only
- provides setAdmin() so Team A's access-level policy can update the shared account record

Password Storage

Each user has a separate ciphered password file:
credentials-<lowercase hex of UTF-8 username>.cip

This allows multiple accounts without storing passwords in SQLite.
Creating a later account stores only the username/access metadata. The associated user sets their own password on first login.

Implemented Audit Design

AuditLogEntry
- id
- username
- action
- content type
- content identifier
- timestamp

AuditLogManager
- implements the existing AuditLogService used by AgencyInterface
- validates required event fields
- generates the access timestamp
- records events through AuditLogStore
- retrieves the audit history

AuditLogStore / SqliteAuditLogStore
- separates audit logic from SQLite persistence
- creates the users and audit_log tables when necessary
- persists the user, operation, content identifier, and timestamp
- returns persisted entries in ID order

Database Tables

users
- username TEXT NOT NULL PRIMARY KEY
- is_admin INTEGER NOT NULL DEFAULT 0

audit_log
- id INTEGER PRIMARY KEY AUTOINCREMENT
- username TEXT NOT NULL REFERENCES users(username)
- action TEXT NOT NULL
- content_type TEXT NOT NULL
- content_identifier TEXT NOT NULL
- accessed_at TEXT NOT NULL

Cross-Team Responsibilities

Team A - Access Levels
- owns standard/admin policy
- first account is supplied by Team D as admin
- Team A owns promotion/demotion rules including preventing self-demotion
- account persistence exposes the shared is_admin field

Team B - User Interface
- owns prompts and menu flow
- if hasUsers() is false, prompts for first account creation
- if a user exists without a password, prompts that associated user to setInitialPassword()
- uses verifyLogin() for login
- displays the audit log only to admins

Team C - Model
- content IDs from briefs, agents, and facilities are passed into AuditLogService

Testing

Manager unit tests use Mockito.
Persistence and cross-component behavior use separate integration tests with temporary SQLite databases.
Existing AgencyInterface integration tests exercise the real AuditLogManager.
