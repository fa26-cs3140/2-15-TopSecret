Homework 5 - Team Member D Test Plan
User Accounts and Audit Log

Requirement

Team D classes are tested for all public methods, including constructors, getters, and setters.
Mockito is used for manager-level unit tests so persistence and file/cipher dependencies are isolated.
Integration tests are stored separately and use real temporary SQLite databases and real ciphered files.

Cross-Team Boundaries

Team A:
- owns promotion/demotion policy and prevents self-demotion
- can use the shared users table/is_admin field

Team B:
- prompts for first-user account creation when no users exist
- prompts a new user to create their own password when passwordExists(username) is false
- uses verifyLogin() for authentication
- displays audit entries through AuditLogService for admin users

Team C:
- provides content identifiers for briefs, agents, and facilities
- AgencyInterface passes those identifiers to AuditLogService

Integration regression additions
- CredentialManager compatibility and first-admin bootstrap
- case-distinct usernames retain independent password files on macOS
- password changes and authentication persist across manager reconstruction
- ciphered file contents exclude plaintext test passwords
- users schema and raw database bytes exclude password data
- shared admin metadata is visible after promotion and demotion
- foreign-key rejection for audit events by unknown users
- audit order and all event fields survive store reconstruction
- database read failures are propagated rather than interpreted as empty stores
- AccountAuditStoreUnitTest mocks JDBC independently of SQLite integration tests
