Homework 4 Planning and Final Changes - Team Member D
User Interface

Bugs First

The Homework 3 UserInterface was originally designed as a one-command file-based utility.

Homework 4 replaces that design with a continuously running mission interface backed by the mission database.

The previous Homework 3 source was retained during planning and then replaced by the Homework 4 implementation after the new tests were defined.

Final Homework 4 User Interface Requirements

The UserInterface begins after successful authentication.

The interface:
- Remains active until Exit is selected.
- Lists available mission briefs.
- Displays mission titles with corresponding numbers.
- Allows the user to select and read a mission.
- Displays the mission title, date, and brief.
- Allows the user to search mission briefs using Team Member C's MissionSearch component.
- Displays matching search results.
- Displays the appropriate message when no search matches are found.
- Returns to the main menu after every operation.
- Handles invalid menu input without crashing.
- Handles invalid mission numbers without crashing.

Final Component Connections

Team Member A - DatabaseManager:
- Owns SQLite access.
- UserInterface does not execute SQL directly.
- UserInterface requests mission titles and records through DatabaseManager.

Team Member B - Authentication:
- Handles username and password validation.
- Authentication occurs before the mission interface begins.

Team Member C - MissionSearch:
- Searches mission brief text.
- Returns a SearchResult.
- UserInterface collects the user's search term and displays the result.

Team Member D - UserInterface:
- Owns terminal input and output for mission operations.
- Maintains the interactive application loop.
- Displays mission lists, individual missions, search results, and error messages.

Final Menu

1. List available mission briefs
2. Read a mission brief
3. Search mission briefs
4. Exit

Unit Testing

UserInterfaceTest uses Mockito.

DatabaseManager and MissionSearch are mocked so UserInterface is tested independently from SQLite and the search implementation.

Unit tests verify:
- Menu output.
- Numbered mission lists.
- Mission display.
- Search-result display.
- No-match messages.
- Invalid menu input.
- Invalid mission numbers.
- Repeated actions during one program session.
- Constructor validation.

Integration Testing

UserInterfaceIntegrationTest uses:
- A temporary SQLite database.
- The real DatabaseManager.
- The real MissionSearch.

Integration tests verify:
- Database-backed mission lists can be displayed.
- A selected database mission can be displayed.
- Real search results can be displayed.
- No-match search messages are displayed.
- Multiple actions can occur without restarting the program.
