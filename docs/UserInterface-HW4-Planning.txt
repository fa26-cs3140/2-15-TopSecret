Homework 4 User Interface Requirements

The Homework 4 UserInterface begins after a user has successfully logged in.

The interface must:
- Remain active until the user selects Exit.
- Allow the user to list available mission briefs.
- Display mission titles with corresponding numbers.
- Allow a user to enter a mission number and display that mission.
- Return to the menu after displaying a mission.
- Provide a Search menu option for Team Member C's search feature.
- Handle invalid selections without terminating unexpectedly.

Component Responsibilities

Team Member A:
- Owns SQLite database access.
- Initializes and manages the mission table.
- Provides mission information to the rest of the system.
- UserInterface must not directly execute SQL.

Team Member B:
- Owns authentication and password management.
- Authentication occurs before UserInterface begins.
- UserInterface does not validate usernames or passwords.

Team Member C:
- Owns mission search.
- UserInterface provides a Search option and displays the results returned by the search component.

Team Member D:
- Owns UserInterface.
- Displays menus, mission lists, mission contents, search results, and error messages.
- Reads the user's menu selections.
- Maintains the interactive menu loop until Exit is selected.

Interface Planning

Homework 4 requires interfaces between system components where appropriate.

The UserInterface should not depend directly on the SQLite implementation.

The exact return types and method names must be decided with Team Member A.

The interface name MissionAccess is currently a planning name only and should be replaced with the team's final agreed-upon interface name.

Search Integration

UserInterface must include an option that allows the user to begin a search.

Team Member C is responsible for performing the search.

UserInterface should:
1. Receive the user's search word or phrase.
2. Pass the request to the agreed search component.
3. Receive the results.
4. Display the matching mission titles or records.
5. Display a no-matches message if there are no results.
6. Return to the main menu.

Authentication Integration

Team Member B's authentication component must complete login before the mission menu begins.

Integration testing should confirm that:
- Valid authentication reaches UserInterface.
- The mission menu is not entered before successful authentication.

Mission Data Integration

Integration testing should confirm that:
- Mission titles stored in SQLite can be displayed through UserInterface.
- A selected mission can be retrieved and displayed.
- UserInterface does not directly perform database access.
- More than one mission operation can occur during the same program session.

Unit Test Plan

UserInterface unit tests should cover:
- Displaying menu options.
- Displaying numbered mission titles.
- Displaying a valid selected mission.
- Handling an invalid mission number.
- Handling invalid menu input.
- Redisplaying the menu after reading a mission.
- Exiting only when the Exit option is selected.
- Performing multiple actions in a single session.

Integration Test Plan

Integration tests should cover:
- Authentication to UserInterface.
- UserInterface to mission database component.
- UserInterface to search component.
- Displaying a selected database-backed mission.
- Displaying search results.
- Displaying a no-search-results message.
- Performing multiple operations without restarting the program.
