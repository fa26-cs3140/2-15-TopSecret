Current agency data model

The maintained ERD and relationship diagram are in docs/team-d/DESIGN.md.
The exact class fields, constructors, and methods are generated from compiled
classes in docs/HW7-ClassDiagram.pdf.

Brief stores its ID, title, ISO date, text, and the legacy nullable missionId.
Agent stores its ID, name, birth/death dates, optional notes, and facilityId.
Facility stores its ID, name, abbreviation, and countryId.
Country stores its ID, editable name, and currently assigned facilities.
Mission stores its ID, title, brief IDs, agent IDs, and facilityId.
Mission assignments are persisted in j_mission_briefs and j_mission_agents.
The current application supports an empty assignment list.

BriefManager, AgentManager, FacilityManager, and MissionManager load these
records. RecordEditor and SqliteRecordStore save complete web edits and their
audit entries in one transaction. RecordRelationships supplies related record
references, and RelatedRecordView renders escaped links in web details.
RecordSearch searches the current content text fields for terminal option 11.

Model objects validate positive IDs and date/string constraints. Database
foreign keys validate references when saving. Mutating a Java model object
alone does not save it to SQLite.

User account metadata and audit entries use users and audit_log. Passwords
remain in per-user ciphered files. Session tokens and activity times live in
the web server process, with a 30-minute inactivity limit.

FacilityManager seeds countries once from the Countries enum and migrates old
facilities by adding country_id. Existing unassigned records remain unassigned
until edited. Country names, links, and forms use the persisted country table.
Country renames are reflected dynamically at assigned facilities.
